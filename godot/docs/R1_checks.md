# R1 open checks (D-20261027-190107), read-only, source of branch Godot (code/ equals PrePort64 for Graphics)

**a. gr_lock / gr_unlock.** Callers: Tmapper, Font, Shade, Scaler (2), aaline, Rect, Pixel, Line, ModelInterp (2), GrSoft. Every call is a bare statement; no caller reads or branches on the result. Dummy and D3D both return 1. Host returns 1, no pixel access. The software draw loops sit between lock/unlock but are only reached through the GrSoft backend, never a gf_ hardware body.

**b. gr_set_palette handoff.** `gr_set_palette_internal` (2d.cpp) stores the palette in `Gr_current_palette`, calls `gf_set_palette`, copies the result back into the caller's palette, then fills `gr_palette` and calls `palette_update`. BmpMan reads `gr_palette` and `gr_palette_checksum` (PalMan), not anything the backend owns. Dummy and D3D `set_palette` are empty, so host stays empty: the host never sees or shuffles palettes.

**c. gr_fog_set.** Callers: ObjectSort (fullneb: set with near/far from `neb2_get_fog_values`, off after the loop), ModelInterp (off, 2 places), FireBalls, Shockwave, Weapons, Ship, StarField, Nebula, TechMenu (all off). Nothing in the 3D library (Render/) calls it; ModelInterp only sets TMAP_FLAG_PIXEL_FOG. Only D3D writes `gr_screen.current_fog_mode/color/fog_near/fog_far`; ObjectSort reads `fog_near/fog_far` and `current_fog_color`, but the only effect of the branch is whether it calls `gr_fog_set` again. Dummy never writes them (the branch is always taken), so host `fog_set` stays a no-op and writes none of them; any later fog state lives inside gr_host. Pixel fog stays a known gap.

**d. gr_save_screen.** Callers: MissionPause, MultiUI (password), multi_pinfo, Popup (2). Dummy returns 0. No caller tests for 0. They branch on the sign only: `id >= 0` (free/restore guards in MultiUI, multi_pinfo, Popup) and `id == -1` (multi_pinfo error). Host returns a non-negative id (a failed capture returns 0 like dummy), so every branch goes the way it goes with the dummy. gr_host unchanged except its comment.
